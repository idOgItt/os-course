# rsh

## Описание

Ваша первая задача - реализовать минималистичную командную строку (shell). В stdin вашему шеллу будут подаваться команды, каждая команда на отдельной строке. Команда представляет собой список слов, разделённых пробельными символами; пробельными символами считаются `' '` и `'\t'`. Количество пробелов между словами может быть произвольным.

Примеры команд:

```console
ls
cat file.txt
echo     Rage   aga1nst the    Fon Neiman machine
```

Первое слово команды - это имя исполняемого файла, который надо запустить (передать первым аргументом в `execvp` или `execlp`). В качестве аргументов подпрограмме нужно передать все слова команды (включая имя файла). Перед запуском `exec` не забудьте сделать `fork`, как обсуждалось на занятии. В родительском процессе после `fork` нужно дождаться, пока дочерний процесс завершится (используйте `waitpid`).

Потоки stdin и stdout должны совпадать у родительского и дочернего процессов.
#### Особые случаи

* Если пользователь ввёл пустую строку (состоящую только из пробельных символов), игнорируйте её и продолжайте работу
* Если вызов `exec` завершился ошибкой, напечатайте "Command not found" и продолжайте работу
* Если подпрограмма завершилась с ненулевым кодом возврата, игнорируйте это и продолжайте работу
* Если поток стандартного ввода (stdin) закончился, завершите работу с нулевым кодом возврата

---
**NOTE**

Чтобы корректно завершить программу необходимо послать специальный символ `"EOF"`, который сигнализирует об окончании stdin. С терминала это делается с помощью сочетания клавиш `Ctrl`-`D`. Останавливая программу используя `Ctrl`-`C` вы посылаете сигнал `SIGINT` который терминирует процесс.

### file

Добавьте в свой шелл поддержку _перенаправления ввода/вывода_.

Будем говорить, что команда требует _перенаправления вывода_, если в начале некоторого слова команды присутствует символ `>`. Вывод необходимо перенаправить в файл, расположенный по пути, записанном в следующем слове команды. Примеры:

```console
$ echo foo >myfile
$ echo foo > myfile
$ echo >myfile foo
$ >myfile echo foo
$ > myfile echo foo
```

Все эти команды эквивалентны. Результатом работы каждой из этих команд должно быть появление файла `myfile` с содержимым `foo` в текущей рабочей директории. Если такой файл уже существует, его содержимое должно быть перезаписано. Обратите внимание, что:

* Требование о перенаправлении вывода может встречаться в любом месте команды;
* Символ `>` может отделяться пробелом от имени файла, следующего за ним, а может не отделяться.

Полностью симметрично введём понятие _перенаправления ввода_. Если команда требует перенаправления ввода, то вместо stdin шелла на вход подпрограмме должно подаваться содержимое указанного файла. Перенаправление ввода указывается символом `<`. Примеры:

```console
$ cat <myfile
$ cat < myfile
$ <myfile cat
$ < myfile cat
```

В результате выполнения каждой из этих команд шелл должен напечатать содержимое файла `myfile`.

#### Реализация

* Чтобы открыть файл, используйте `open` с соответствующими флагами
* Чтобы получить номера дескрипторов stdin и stdout, используете константы `STDIN_FILENO` и `STDOUT_FILENO`
* Чтобы создать копию файлового дескриптора `old` со зачением `new`, используйте `dup2(old, new)`. Заметьте, что если `new` уже был открытым фаловым дескриптором, то этот дескриптор будет закрыт

### pipe

Вишенкой на торте вашего шелла будет поддержка пайпов.

Пайплайном будем называть синтаксическую конструкцию следующего вида:

```console
$ {command} | {command} | ... | {command}
```

Здесь `{command}` - команда в смысле прошлых задач, `|` - символ, называемый пайпом. Шелл исполняет пайплайн следующим образом:

* Stdout подпроцесса первой команды подаётся на stdin подпроцессу второй, stdout второй на stdin третьей и т.д.;
* Подпроцесс первой команды берёт stdin либо из файла, указанного перепаравлением stdin (см. прошлую задачу), либо из stdin шелла, если перенаправление не указано;
* Аналогично, подпроцесс последней команды выводит stdout либо в файл, указанный перенаправлением stdout, либо в stdout шелла, если перенаправление не указано.

Примеры корректных пайплайнов:

```console
$ cat < infile > outfile
$ cat < infile | head -c 50 | wc -l > outfile
$ echo hello |tail -n 10 |wc -c
```

Каждый пайплайн подаётся в шелл на отдельной строке. Перед тем, как считывать следующую строку, шелл ждёт завершения последнего процесса пайплайна.

Заметьте, что:

* Перенаправление stdin можно указывать только у первой команды пайплайна, перенаправление stdout - только у последней;
* Символ пайпа может как отделяться пробелом от следующего слова, так и не отделяться (от прошлого слова в нашей реализации шелла он всегда отделяется пробелом).

#### Реализация

* Чтобы связать stdin одного подпроцесса с stdout другого, используйте `pipe` и `dup2`;
* Обратите внимание, что в родительском процессе необходимо закрывать файловые дескрипторы, соответствующие больше не нужным в рамках данного процесса концам пайпов. Если их не закрывать, у вас, во-первых, начнут течь файловые дескрипторы (их количество на процесс ограничено), во-вторых, запущенные в пайплайне команды могут зависать (до тех пор, хотя бы у одного процесса есть незакрытый write-конец пайпа, читающий из read-конца не получит EOF).

## Особенности rust

1. Для чтения входного потока используйте конструкцию `for line in io::stdin().lock().lines()`
2. Функция парсинга команды должна быть отделена от исполнения. Сигнатура этой функции вам уже дана.
   `pub fn parse(line: &str) -> Vec<Command>`.
3. Функции работы с системными вызовами ожидают C-строки в качестве аргументов. С-строки отличаются тем, что оканчиваются на символ `\0`. Строки rust таким свойством не обладают, поэтому нужно будет делать явную конвертацию.
  - Чтобы сделать новую C-строку нужно использовать конструкцию `CString::new(arg)`, где вместо `arg` можно подставить типы `&str`, `&[u8]`, `Vec<u8>`, `String`.
4. Чтобы представить одну команду используйте структуру `Command`.
    ```rust
    pub struct Command {
        pub command: Vec<CString>,
        pub stdin: Option<CString>,
        pub stdout: Option<CString>,
    }
    ```
   Сама команда - это вектор аргументов и два опциональных перенаправления для `stdin` и `stdout`.
   Чтобы работать с `Vec` вам хватит метода `push` и обращения по индексу.
   Чтобы создать `Option` используйте выражения `Some(path)` или `None`.
   Чтобы прочитать `Option` удобно использовать конструкцию `if let Some(path) = &cmd.stdin`. В этом случае, если в `stdin` есть значение, в переменной `path` появится ссылка на это значение.
5. Некоторые системные вызовы ожидают аргументом тип удовлетворяющий `NixPath`.
   `fn open<P: ?Sized + NixPath>(path: &P, oflag: OFlag, mode: Mode) -> Result<RawFd>`. Чтобы получить `NixPath` из `CString`, нужно позвать метод `as_c_str()`.
6. `execvp` имеет сигнатуру `fn execvp<S: AsRef<CStr>>(filename: &CStr, args: &[S])`.
   Вместо первого аргумента можно передать `&CString`, а вместо второго `&Vec<CString>`.
    ```rust
    let cmd: Command;
    // типы указаны для большей наглядности
    let program: &CString = &cmd.command[0];
    let args: &Vec<CString> = &cmd.command;
    execvp(program, args)?;
    ```
7. Для обработки ошибок системных вызовов проще всего использовать `?`.
