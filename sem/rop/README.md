# rop

ROP - расшифровывается как return oriented programming. Техника
позволяющая выполнять произвольную последовательность ассемблерных
инструкций. Обычно используется в связке с другими трюками, чтобы
превращать ошибки работы с памятью в исполнение произвольного кода.

Допустим атакующий хочет выполнить 3 инструкции, но ровно такой
последовательности инструкций в исполняемой файле нигде нет.

```
        mov rsi, rdi
        add rsi, 1
        shl rsi, 1
```

Техника состоит из 2-х шагов. На первом шаге атакующий ищет внутри
исполняемого файла "гаджеты".  Гаджет - это последовательность
инструкций заканчивающаяся инструкцией `ret`. Допустим в файле нашлось
3 гаджета:

```
0x400426:  mov rsi, rdi
0x400429:  ret
...
0x40051d:  add rsi, 1
0x40051f:  ret
...
0x400e23:  shl rsi, 1
0x400e26:  ret
```

Что будет, если положить на стек последовательно 3 указателя на эти
гаджеты и выполнить инструкцию `ret`?

```
           STACK

         0x400e23
         0x40051d
  rsp -> 0x400426
```

Выпишем trace исполнившихся инструкций:

```
           ret # первый ret переходит к адресу на вершине стека и сдвигает стек на 8
0x400426:  mov rsi, rdi
0x400429:  ret # следующий адрес, стек сдвигается еще на 8
0x40051d:  add rsi, 1
0x40051f:  ret # то же самое
0x400e23:  shl rsi, 1
0x400e26:  ret
```

Видно, что выполнилать требуемая последовательность, но между
инструкциями были еще выполнены `ret` и `rsp` в итоге увеличился на
32.

## Задача

Вам необходимо составить ropchain, результатом работы которого будет
число 0xdeadbeef в регистре `rax`. Функция `make_ropchain` в файле
`src/ropchain.rs` должна заполнить буфер и получившеюся его часть
в виде среза.

В качестве гаджетов нужно использовать отрывки кода из файла
`src/lib.rs`. Адреса гаджетов доступны вам в векторе,
который возвращает функция `gadgets()`. Кроме
гаджетов на стек ничего класть нельзя.
